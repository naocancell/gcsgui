## 1. 项目背景与重构动因

GCSGUI 作为无人机地面测控站系统的前端底座，集成了三维地理信息（Cesium）、航线规划、多机高频遥测监控（10~50Hz）、通信链路健康检测与桌面端多窗口（Tauri IPC）交互。随着系统功能不断演进，前期代码暴露出严重的架构腐化与内存性能瓶颈：

```
                                  ┌──────────────────────────────────────────────┐
                                  │            重构前核心架构痛点全景            │
                                  └──────────────────────────────────────────────┘
                                                          │
                 ┌────────────────────────────────┬───────┴────────────────────────┬────────────────────────────────┐
                 ▼                                ▼                                ▼                                ▼
       【目录语义严重错位】             【上帝单体组件丛生】             【多代代码与死代码断层】         【内存膨胀与泄漏隐患】
    • 核心引擎塞入 assets/js         • toolbar.vue: 3,040 行          • 重构残留未引用的几何文件       • 主窗口冷启动 300MB+
    • 页面与组件混在 components      • RouteManage: 2,463 行          • 同时引入 turf 与 @turf/turf    • 高频遥测深度 Proxy 堆积
    • 伪路由拦截强切全局状态         • 单组件包揽网络/窗口/图层/分析  • 大量历史 .js 遗留，TS 逃逸     • ECharts/IPC 监听未销毁
```

### 1.1 核心痛点详述

1. **目录语义严重错位**：
   `src/assets/js/` 目录下放置了 `RouteManageViewer.js`（86KB）、`measureViewer.js`（84KB）、`NFZViewer.js`、`websocketProtocol.ts` 等**系统最核心的 GIS 视口与测控协议引擎**。在现代前端工程中，`assets/` 仅应存放图片、字体、静态模型等静态资源。这种错位导致架构分层失效，新人员无法依据现代前端规范定位核心逻辑。
2. **上帝单体组件（God Component）丛生**：
   * `src/components/toolbar.vue`（3,040 行）：一个工具栏组件，实际包揽了 Tauri 多窗口拉起/管理、WebSocket 协议中继、三维空间分析、电子围栏逻辑、DOM 事件以及 10 余个弹窗的状态机。
   * `RouteManagePage.vue`（2,463 行）：堆叠了航线列表、航点表格、剖面分析图表、天气图表与三维航线交互，单文件认知负荷极大。
3. **“伪路由”扭曲了 Vue Router 的生命周期**：
   页面放置在 `components/page/` 下；`router/index.js` 在守卫拦截中将 `/routeManage` 强行重定向到 `Home`，并修改 `staticStore.showRouteManage = true`，在 `HomePage.vue` 内部用 `v-if` 条件渲染页面，导致 URL 状态与页面组件生命周期彻底割裂。
4. **内存膨胀与常驻压力**：
   * **主窗口 300MB+**：Cesium 默认开启极大瓦片缓存和全量渲染特性，高频无人机遥测数据（每秒数十包）被直接放入 Vue 深度响应式 `ref` / Store 中，导致每秒创建海量深度 `Proxy` 与 `Dep` 依赖追踪对象，引发严重堆内存常驻与垃圾回收（GC）卡顿。
   * **子窗口 70MB/个**：Tauri 物理子窗口拉起独立 Chromium 渲染进程的固定开销，加之缺乏图表和事件监听器的显式销毁机制，存在内存随运行时间线性上涨的风险。

## 3. 核心模块重构与解耦详情

### 3.1 三维 GIS 核心引擎解耦与迁移（`src/core/gis/`）

* **彻底删除 `src/assets/js/`**：将 `RouteManageViewer.js`、`measureViewer.js`、`NFZViewer.js` 等核心类统一迁移至 `src/core/gis/`，并全量升级为强类型 TypeScript。
* **补齐完整的生命周期销毁机制（`destroy()`）**：
  在以往的设计中，Viewer 类创建了大量的 `ScreenSpaceEventHandler`、Cesium 实体（`entities.add`）和 DOM 悬浮菜单，在页面切换或组件销毁时无法释放。重构后，每个核心 Viewer 均实现了标准化 `destroy()` 方法：

```typescript
// src/core/gis/RouteManageViewer.ts (代码节选)
public destroy(): void {
  // 1. 注销屏幕空间事件监听器
  if (this.handler && !this.handler.isDestroyed()) {
    this.handler.destroy();
    this.handler = undefined;
  }
  if (this.editHandler && !this.editHandler.isDestroyed()) {
    this.editHandler.destroy();
    this.editHandler = undefined;
  }
  // 2. 清理全局键盘与右键事件监听
  this.removeKeydownListener();
  this.removeEditKeydownListener();
  // 3. 清除动态添加的 Cesium Entity 实体与标牌
  this.clearTemporaryEntities();
  this.clearAllRouteEntities();
  // 4. 移除动态注入的 DOM 弹窗节点
  if (this.drawMenuEl && this.drawMenuEl.parentNode) {
    this.drawMenuEl.parentNode.removeChild(this.drawMenuEl);
    this.drawMenuEl = undefined;
  }
}
```

* **业务逻辑完全内聚在 Composables 中**：例如 `useSimulatedFence.ts` 专门管理模拟电子围栏实体的绘制与告警检测，`useToolbarTelemetrySync.ts` 专门管理 Tauri 跨窗口遥测广播。

### 3.3 超大上帝组件解耦：`RouteManageView.vue`（2463行 ➔ 471行）

`RouteManageView.vue` 原先堆积了航线文件 I/O、航点修改、高程剖面图、气象图表等所有逻辑。重构后拆分为 **1 个主视图 + 4 个子面板组件 + 4 个专业 Composables**：

1. **子组件拆分**：
   * `RouteListPanel.vue`（航线列表增删、显隐、锁定、导入/导出操作）；
   * `RouteWaypointTable.vue`（航点经纬度、高度、速度参数编辑表格）；
   * `RouteProfilePanel.vue`（高程剖面与地形安全高程分析容器）；
   * `RouteWeatherPanel.vue`（沿途气象与风速多轴图表面板）。
2. **逻辑抽离至 Composables**：
   * `useRouteEditor.ts`：负责与 `RouteManageViewer` 三维视口交互状态同步；
   * `useRouteFileIO.ts`：负责航线 KML/JSON 文件的解析校验与本地存储；
   * `useRouteProfileChart.ts`：负责高程剖面 ECharts 的数据生成与生命周期管理；
   * `useRouteWeatherChart.ts`：负责气象多维图表的绘制与销毁。
* **重构结果**：`RouteManageView.vue` 主文件行数由 **2,463 行缩减至 471 行**（缩减 80.9%），所有拆分出的子文件单文件行数均在 100~300 行之间。

### 3.4 顶层视图与原生路由体系重构（`src/views/` 与 `src/router/`）

1. **确立顶层视图目录 `src/views/`**：
   将页面级视图统一提升至 `src/views/`（`HomeView.vue`, `RouteManageView.vue`, `TelemetryView.vue`, `LinkHealthView.vue`），并在根目录下保留兼容别名，消除了组件层与页面层的混乱。
2. **消除伪路由重定向与 Store 强耦合**：
   重构前在 `router.beforeEach` 里通过修改 `staticStore.showRouteManage = true` 强行阻断路由并重定向到 Home 的反模式被彻底拆除。
3. **严格 TypeScript 路由配置**：
   `src/router/index.ts` 全量迁移至 TypeScript，使用 `createWebHashHistory` 完美适配 Tauri 桌面环境与子窗口哈希路由，并在 Node.js / 测试环境中自动安全降级为 `createMemoryHistory`。

## 4. 性能与内存深度治理专项

针对地面站系统长时间运行中出现的**主窗口 300MB+** 与**子窗口 70MB/个**的内存常驻问题，本次重构实施了全方位的性能治理：

```
┌──────────────────────────────────────────────────────────────────────────────────────────────────┐
│                                     性能与内存深度优化矩阵                                       │
├──────────────────────────┬───────────────────────────┬───────────────────────────────────────────┤
│         优化专项         │         技术实施手段      │                 预期成效                  │
├──────────────────────────┼───────────────────────────┼───────────────────────────────────────────┤
│ 1. 高频遥测响应式解包    │ shallowRef + markRaw      │ 彻底消除每秒海量 Proxy/Dep 内存常驻与 GC 抖动 │
│ 2. Cesium 3D 引擎调优    │ tileCacheSize: 100 + 按需渲染 │ 压降三维视口显存与堆内存占用 50MB~100MB+  │
│ 3. 生命周期内存闭环      │ ECharts dispose + IPC unlisten│ 杜绝图表与全局事件监听导致的内存线性泄漏  │
│ 4. 依赖包瘦身            │ 移除旧版 turf 依赖        │ 降低打包体积与 V8 引擎解析内存负担        │
└──────────────────────────┴───────────────────────────┴───────────────────────────────────────────┘
```

### 4.1 高频遥测（10~50Hz）响应式解包（`shallowRef` 与 `markRaw`）

* **问题机理**：无人机遥测报文结构复杂，每秒接收 10~50 次。若将完整嵌套对象直接存入 Vue 3 的 `ref()`，Vue 会递归遍历对象的每个属性并建立 `Proxy` 拦截，创建数万个 `Dep` 依赖收集器。这会导致堆内存急剧膨胀，并在垃圾回收时产生明显的界面微卡顿。
* **重构落地**：
  * 在 `uavStore.ts`、`useTelemetryStore.ts` 中，将高频遥测状态全面重构为 `shallowRef`：
    ```typescript
    // src/store/uavStore.ts (节选)
    export const useUavStore = defineStore('uav', () => {
      // 采用 shallowRef 避免 Vue 对每秒数十次的高频遥测数据进行深度递归代理
      const uavInfo = shallowRef<UAVInfo | null>(null);
      const telemetryFrames = shallowRef<TelemetryFrame[]>([]);
      
      function updateUavInfo(newInfo: UAVInfo) {
        // 通过直接替换引用触发浅层响应式更新
        uavInfo.value = { ...newInfo };
      }
      return { uavInfo, updateUavInfo };
    });
    ```
  * 对所有挂载到 Store 中的 Cesium 内部实例（如 `Viewer`, `ImageryLayer`, `DataSource`）一律使用 `markRaw()` 标记为不可代理对象。

### 4.2 Cesium 3D 引擎内存调优与按需渲染

在 `src/utils/map/sceneViewer.ts` 中针对测控地面站场景进行了深度定制：

```typescript
// src/utils/map/sceneViewer.ts (调优配置)
export function perfViewer(viewer: Viewer) {
  // 1. 限制地形与影像瓦片缓存上限为 100 张（默认数百上千张，极大占用显存和内存）
  viewer.scene.globe.tileCacheSize = 100;
  
  // 2. 开启仅三维模式，禁用 2D / 哥伦布视图的冗余着色器与投影几何计算
  // (在初始化参数中指定 scene3DOnly: true)
  
  // 3. 启用按需渲染模式 (Request Render Mode)，无相机移动或实体变动时 GPU 停止空转
  viewer.scene.requestRenderMode = true;
  viewer.scene.maximumRenderTimeChange = 0.05;
  
  // 4. 彻底移除原有的逐帧 preRender 暴力轮询监听器
}
```

## 6. 后续开发与架构维护规范

为保证重构后的架构整洁性并防止后续开发中再次引入技术债务，制定以下开发红线与维护规范：

### 6.1 开发红线（Critical Rules）
1. **严禁在 `src/assets/` 下新增任何 `.js`/`.ts` 业务逻辑文件**；所有业务或三维引擎代码必须归入 `src/core/gis/` 或 `src/composables/`；
2. **严禁单文件代码量超过 500 行**；若组件逻辑膨胀，必须及时按子面板（`components/`）或业务 Hook（`composables/`）进行拆解；
3. **高频数据严禁使用深层响应式**；所有无人机遥测、高频传感器报文必须使用 `shallowRef`，Cesium 内部对象必须使用 `markRaw`；
4. **图表与全局监听必须实现销毁闭环**；凡是在组件中初始化的 ECharts 实例或 `@tauri-apps/api/event` 监听，必须在 `onBeforeUnmount` 中显式调用 `.dispose()` 与 `unlisten()`。

### 6.2 架构演进路线（Roadmap）
* **单窗口虚拟停靠布局（解决 70MB/子窗口物理开销）**：
  目前遥测与链路健康窗口使用 Tauri 的物理 `WebviewWindow`。若后续对内存有进一步极限压降需求，可在前端引入浮动停靠窗口库（如 Golden Layout / Vue-Grid-Layout），将物理子窗口演进为同一 WebView 内部的虚拟停靠面板，即可将每个子面板的增量内存从 **70MB 彻底降至接近 0MB**。
